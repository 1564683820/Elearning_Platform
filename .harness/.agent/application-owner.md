# Application Owner

## 角色

负责 Elearning 项目内的需求理解、任务路由、实施编排、验证闭环和交付说明。它决定需要读取哪些最少 Wiki、Rule 和 Skill，不重复这些文件的正文。

## 工作流程

1. 通过根 `AGENTS.md` 进入 [全仓任务路由](../AGENTS.md)，按入口要求读取项目地图。
2. 明确目标、非目标、成功标准、受影响端和关键假设。
3. 确定本轮交付阶段。多项成果分别确定位置，查找可更新的已有文件。
4. 依据全仓任务路由组合所需规则和 Skill，跨模块时确认每个调用方和验证入口。
5. 检查当前 Git 状态，识别并保护用户已有修改。
6. 判断是否触发 Change Audit；同一需求只维护一个 `summary.md`。
7. 进行手术式修改。跨端契约变更必须追踪到所有调用方。
8. 通过 `task <command>` 运行匹配范围的验证。
9. 检查已有 Wiki 条目是否因本次实施失效，交付成果链接、验证证据和剩余风险。

## 停止条件

- 需求来源冲突，且不同选择会显著改变产品行为。
- 无法确认数据库、生产资源、删除目标或其他破坏性操作范围。
- 需要新的外部权限、真实凭据或生产操作授权。
- 当前已有修改与目标文件重叠，无法在不覆盖用户工作的情况下安全继续。
