## F01：区分认证失效与角色权限失败

目标：缺失/错误认证返回可供客户端重新登录的 401，真实角色拒绝保留 403；异常用户主体在进入数据库前拒绝。非目标：修改角色规则、增加账号吊销策略或改变轻量下载/WebSocket 不查数据库的既有行为。关键假设：User.id 为正数、有符号 BIGINT，JWT sub 由现有 create_token 写为十进制字符串。

复现：HTTPBearer 默认在缺失/错误 scheme 时直接 403，与已过期 Token 的 401 不一致；小程序仅 401 会清除过期登录并提示。多个依赖直接 int(payload.sub)，非数字主体抛异常，非正/越界主体仍进入查询（Mock 场景下可继续或返回角色 403），缺少统一主体边界。

修复：普通 Bearer 解析改 auto_error=False，由 get_current_user 对无凭据明确返回 401 + WWW-Authenticate: Bearer。复用主体解析，限制 ASCII 十进制字符串、正数与 signed BIGINT 范围；普通用户、扫描、两类下载依赖返回 401，WebSocket 保留 ValueError 失败方式。未改变教师/管理员角色检查与资源归属条件；扫描 purpose 仍不能访问普通/下载/WS。

兼容影响：未登录/错误认证头从原 403 改为 401；权限不足继续 403。小程序现有请求层会在 401 提示登录、403 保留 Token；Web Axios 保留响应状态，由既有调用方展示错误，未新增自动注销。query token 下载与专用扫码入口保持原传参方式。

验证：新增 7 项真实认证依赖/内存 HTTP 测试，覆盖缺失/Basic/空 Bearer、无效/过期 Token、非法/非正/BIGINT 越界主体、普通用户/教师/管理员矩阵、被删用户、扫描隔离和有效 Snowflake 精度。完整后端 discover 72 项通过；`node --test wechart/tests/request-errors.test.cjs web-admin/tests/api-client.test.cjs` 7 项通过；`./harness.ps1 verify` 退出码 0（182 文件语法、Harness、Web 类型检查）。数据库查询为 Mock，没有真实用户认证或写入。

限制：角色矩阵只证明所测共享依赖，不代表所有业务资源权限正确；真实 MySQL、浏览器/小程序登录跳转与账号吊销联调未完成。轻量下载/WS 仍只校验 Token，不新增用户存在性检查。没有轮换密钥、改变密码或访问真实账号数据。
