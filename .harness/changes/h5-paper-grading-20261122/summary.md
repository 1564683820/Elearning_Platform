# H5 问答助手与纸质批卷

- Audit-ID：h5-paper-grading-20261122
- 类型：跨端功能
- 日期：2026-11-22

## 目标与成功标准

- 教师使用现有账号在 H5 与网页端小 e 打开同一会话并续聊。
- 教师在 H5 配置试卷、模板和本卷答案，使用产品提供的固定答题卡拍摄、复核和确认，并在两端查到一致的成绩及统计。
- 页面按 Pencil 画板逐项核对，包括失败、空态和弹窗。[Pencil](../../../product/design/H5design.pen) · [首页方案](../../../docs/plans/features/2026-11-22-H5首页问答助手开发方案.md) · [试卷方案](../../../docs/plans/features/2026-11-22-H5试卷功能开发方案.md)

## 非目标

- 引入单独的 H5 后端、重复的成绩数据或自定义答题卡印制。

## 关键决策

- 在 `H5app` 工作区落地独立 Vite 入口，沿用网页端 React 依赖、教师认证、同一教学助手和试卷 API。两端共用 SSE 解码。
- 固定版式未核定时，草稿编辑与原件预览仍可使用，两个端的固定卡扫描入口按共用校验禁用。
- 网页端和 H5 使用同一个纸质草稿编辑器。名称、班级和备注保存在现有试卷字段，应用时的题量、选项、分值和本卷答案保存在题目列表，模板 ID 和版本摘要保存在答题卡配置。草稿版本按内容校验，重复编辑旧版本返回冲突。变更模板前确认清空本卷答案。纸质草稿保持未发布，已有线上试卷继续使用原入口。
- 历史批改先从 `teacher_exam` 和 `exam_submission` 计算。卷名与已归属教师的试卷匹配，引用只携带试卷及题号。查询有效答卷时过滤待评、未识别身份及重复考号，选项统计只传聚合数据。同一服务用于普通与流式问答。
- H5 批改记录按试卷属主读取，支持无班级试卷。问答与记录共用有效成绩判定，历史重复考号保留可追溯但不计入有效成绩。照片由鉴权端点读取服务端已关联的扫描文件。
- 两份开发方案按 Pencil 画板补充 H5 路由、共享组件和服务端目录，核对原表复用、派生数据、追加列和共用迁移链。两个端共用现有业务表和 Milvus 集合。发布前需核验旧链缺失的 `0012`。

- 固定手写卡技术方案补齐共享拍摄、矫正覆盖检查、逐格复核和实际题号判分。两张参考图按各自版式设计验证用例，正式识别仍待取得同版空白卡及脱敏填写样张。[技术方案](../../../docs/plans/features/2026-11-22-H5试卷功能开发方案.md#固定手写卡技术开发方案)

## 模块级变更

- `client/h5/` 提供登录、首页、右侧会话栏、设置页、试卷列表、详情、模板、草稿表单、记录入口、拍照预览和我的页面。
- `client/src/api/` 提供共享请求、SSE 解码和既有手工保存试卷入口。新增的 Vite 开发端口为 5174。
- `server/app/services/exam_knowledge.py` 提供正式成绩聚合，`server/app/api/v1/exam.py` 提供重新鉴权的单题统计。H5、网页端小 e 和悬浮助手在消息中展示相同来源，单题页共用 React 组件。
- `client/src/shared/exams/Records.tsx` 提供两端批改记录筛选、成绩详情、照片预览和已有修正历史。后端复用提交、扫描和批改日志表，按最近更新时间分页读取。
- `client/src/shared/exams/PaperDraftEditor.tsx` 与 `server/app/services/paper_draft.py` 提供创建、续编及模板快照。网页端试卷列表与 H5 试卷详情都能打开纸质草稿。旧版写分、发布和重新生成卡片入口会拒绝待配置的纸质草稿。
- 原件沿用 `user_document` 保存试卷关联及顺序。网页端和 H5 共用上传、重试和预览。PDF 分页渲染，图片可预览，DOCX 可下载。原件内容存于私有目录 `PAPER_SOURCE_DIR`，同卷同名同内容去重。
- 评分模板沿用 `answer_sheet_template`，增量迁移只增加 `archived_at`。Web 与 H5 共用停用接口。原模板仅从可选列表排除，已建卷继续使用保存的名称、题目设置和本卷答案。Web/H5 模板 API 读取精确的字符串 ID；H5 按 ID 和版本编辑，创建遇到同名模板由服务端返回冲突。H5 选择模板时能就地创建并自动应用。
- `server/app/services/chat_attachments.py` 复用 `user_document` 与已有文本和 OCR 提取，结构化上传通过原教学助手路由，沿用旧客户端上传契约。附件和用户消息同事务关联，普通和流式问答均注入同一会话的附件资料并返回来源。网页端小 e 与 H5 共用附件发送和读取代码。私有文件由 `CHAT_ATTACHMENT_DIR` 配置。
- 问答 Skill 上传、列表和文件校验已由 H5 与网页端复用，使用 `agent_skill` 的 `qa` 类型。只增加可空的原文件名字段，旧记录继续以技能名生成展示文件名。单份 Skill 最大 48 KiB，保存时校验 UTF-8、Markdown 文件名和 YAML 中的 `name`，并按教师检查同名。当前只存文档和元数据。
- H5 从扫描入口和批改记录进入固定卡待复核列表。复核页面提供逐题修正、考号和班级花名册选择、保存待复核反馈、重复成绩确认及重批结果。班级和考号沿用教师班级接口，H5 批改请求与网页端共用 `teacherApi` 封装。
- 固定卡后端增加待复核列表、详情、考号及作答修正、正式确认和同身份重批。内部识别入口核验固定版式、请求重试和照片摘要。复用扫描、成绩与日志表，确认时同事务更新 SQL 错题数据，待复核答卷不进入有效成绩。
- 固定卡原图以试卷及内容摘要保存在私有目录，沿用 `exam_scan_record.scan_image_url` 引用。复核、成绩记录分别按扫描和当前成绩鉴权读取。重批后当前成绩显示新原图，旧扫描继续保留自己的照片。两端在复核和成绩记录使用同一个 Pencil 原图组件。
- 网页端试卷列表和纸质草稿可进入待复核及批改记录。与 H5 共用逐题修正、花名册、确认、重批、照片及结果组件。草稿中的快捷入口沿用离开前的保存或放弃提示。网页端确认后可继续核对下一份。
- 两端接通纸质结束批卷及补批。复用试卷配置 JSON 保存完成时间和状态版本，试卷列表、详情和网页草稿显示同一口径。事务在待复核清空且已有有效成绩后才能结束。H5「询问本卷」将试卷名称带入小 e 输入框，由教师确认发送。
- 两端支持放弃待复核和撤回已确认成绩。放弃保留原图、原因与时间，最后一份待复核放弃且无正式成绩时可重新配置评分。撤回写成绩版本与批改日志，移除 SQL 错题，原图和分数留作历史。同考号再次确认更新同一行。
- 两端单题核对按 Pencil 画板 45 展示原始识别和标准答案，支持更正为单选、空白或确认多涂。多涂使用现有作答值保存教师核定的选项，保留扫描原值，单选题按无效填涂记零分。成绩明细和问答分别展示无效填涂和空白。
- 两端共用相机及文件上传。服务端从固定版式登记目录加载参考图和题位，完成匹配、对齐和填涂采样。上传按试卷、教师、请求 ID 与照片摘要去重。成功进入复核，失败记录保留原因和可鉴权读取的原图。
- 小 e 普通、流式发送复用 `chat_message` 的请求标识和回复关联。问题、附件绑定及最终回复在同一事务提交。Web 主页面和 H5 断流时按原请求查询已保存回复，重试同一问题及附件复用原标识。上游流缺失结束标志时不保存部分回答。
