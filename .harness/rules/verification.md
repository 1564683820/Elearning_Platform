# 验证规则

## 适用范围

适用于任何代码、依赖、构建、配置、迁移或 Harness 变更。

## 必须

- 验证必须从仓库根目录通过 `harness.ps1` 统一入口执行，或在交付中明确说明等价底层命令。
- 仅 Harness/文档变更：至少运行 `task lint`。
- 后端 Python 变更：至少运行 `task test`；涉及数据库或外部服务时，另做定向集成验证。
- 后端行为变更：追加 `task unit`；该套件的外部服务替身和 SQLite 测试不能替代 MySQL、Redis、Milvus 或模型在线验收。
- Web 变更：至少运行 `task typecheck`；发布相关修改运行 `task build`。
- 小程序变更：运行 Harness 检查，并在微信开发者工具中完成编译/相关页面回归；无法自动化时明确标注未执行。
- 跨端或架构变更：运行 `task verify`，再补充相关集成验证。

## 证据要求

- 记录实际命令、退出码和关键结果。
- 现有 `test` 只是 Python 语法编译回归，不得称为完整后端单元测试。
- 现有 `lint` 只是 Harness 结构和 Git 空白错误检查，不得称为 Python/TypeScript 风格检查。
- 因依赖、凭据、平台工具或外部服务无法运行的验证，必须说明原因和风险，不得伪造通过结果。

## 禁止

- 禁止为了获得绿色结果而删除测试、吞掉错误、放宽契约或跳过必要步骤。
- 禁止将历史构建产物存在视为当前源码构建成功。
