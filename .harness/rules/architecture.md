# 架构规则

Elearning 采用模块化单体。后端按教学任务、考试与判卷、教材与词汇、账号与权限等业务模块划分。沿用现有运行入口，业务迭代时逐步收拢相应模块。

- FastAPI 路由处理输入、身份与响应。Worker 负责调度。审核、发布和重试等业务动作放在所属模块的服务中，供对应入口复用。
- 业务服务依赖所属模块的模型、持久化和集成代码。跨模块复用通过对方公开的服务函数。 `server/app/services/` 禁止导入 `app.api` 和 `app.routers`。
- 状态流转和业务计算优先写成可单测的 Python 逻辑。SQLAlchemy、Redis、Milvus 和模型调用集中在对应服务或集成模块。
- Web 和小程序页面通过各端的 API 封装发请求。发生公开契约变更时，按 [HTTP API 规则](http-api.md) 检查调用方。

教学任务可以作为参考。路由和 Worker 分别处理 HTTP 请求与任务调度，业务状态由 `TeachingTaskService` 管理。

## 客户端独立启动

- Web 管理端、微信小程序、H5、原生 App 等客户端各自拥有独立的本地开发启动入口。新增客户端时，须提供并记录该端的启动命令或平台开发工具入口。单独启动某一端时，无需启动其他客户端。
- 各客户端可以共用后端 API、基础设施和公共代码。需要同时运行的客户端，其本地开发端口、运行配置和构建输出应按端区分，避免相互冲突。
- 仓库可提供多端联合启动命令。联合启动应复用各端已有的启动入口，并保留各端独立启动的能力。

### 开发命令设计

- 根目录 `Taskfile.yml` 提供开发命令索引和编排。可通过命令行启动的客户端使用 `dev-<端名>`，例如 `dev-web`、`dev-h5`、`dev-app`。仅通过平台开发工具启动的端，在根 README 记录工具和项目入口。
- 单端命令转发到该端的启动入口。依赖现有 Harness 运行环境的任务由 Task 调用 `harness.ps1`，端口和运行参数由所属应用配置管理。
- `dev` 并行启动 Web 管理端和 H5。新增客户端保留独立命令，加入联合启动范围时同步更新 README。后端通过 `dev-backend` 单独启动。
- 联合命令在启动任何客户端前检查所需入口。验收启动命令时须检查单端运行、联合运行和退出后的进程及端口释放。
