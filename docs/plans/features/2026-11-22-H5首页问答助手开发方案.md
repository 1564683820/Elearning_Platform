# H5 首页问答助手开发方案

**目标**　为网页端小 e 增加 H5 入口，让同一教师跨端续聊，并能直接询问历史批改情况，或附上文件和图片提问。

**架构**　两个 React 界面共用教学助手 API、会话库和问答服务。试卷模块提供正式批改数据，小 e 统一检索、组织上下文和引用。H5 按设计稿组装移动界面，桌面端也接入本次新增的公共能力。

**依据**　[PRD v0.5](../../../product/prd/批卷H5端-PRD.md) · [Pencil 设计稿](../../../product/design/H5design.pen) · [交互预览](../../../product/design/H5design/motion-preview.html) · [试卷开发方案](./2026-11-22-H5试卷功能开发方案.md)

## 数据库设计

网页端小 e 与 H5 使用同一教师 ID、教学助手会话 ID 和消息 ID。沿用现有 MySQL 表与 Milvus 集合，新增业务表为 0。两个客户端按同一会话读取已有消息、摘要和上下文。教师身份复用 `user.id`，历史归属复用 `chat_conversation.user_id`。附件与批改统计分别从文档与试卷域原表查询。

| 数据 | 复用的表与字段 | 读写规则 |
| --- | --- | --- |
| 会话与上下文 | `chat_conversation.id, user_id, type, title, summary, class_id, status, updated_at` | 教学助手沿用 `type=4`。两端按同一会话加载摘要、历史及引用。已有 `class_id` 可收窄网页端显式指定的范围，H5 从对话理解试卷和班级范围。 |
| 消息与引用 | `chat_message.id, conversation_id, role, content, message_type, sources, created_at` | 共用历史分页、回复和引用结构。批改引用在现有 `sources` 扩展试卷 ID、题号、统计时点及计数。 |

### 字段复用与写入边界

- **跨端会话**　同一教师读写既有教学助手会话和消息。会话列表沿用 `chat_conversation.updated_at` 排序。待发送草稿属于当前端。网页小 e 主页面和 H5 按教师、端和会话在当前浏览器标签页保存文字、已上传的附件引用和重试标识。尚未上传的本地文件在切换会话时保留，刷新浏览器后需要重新选择。提交前无需写入会话或消息表。
- **会话附件**　文件复用文档存储，消息通过 `user_document.chat_message_id` 反查附件。聊天附件只写消息关联，试卷原件只写试卷关联与顺序，两种用途由既有 `doc_category` 区分。
- **历史批改**　题目和标准答案来自 `teacher_exam.questions`，已确认作答和逐题判分来自 `exam_submission`。正确率和选项分布按有效成绩查询。单题来源沿用 `sources`，附上 `exam_stats` 中的有效份数、答对份数、统计时点及唯一最高错选。H5、网页小 e 和悬浮助手共用统计展示，历史消息兼容缺少该字段的来源。`chat_message.sources` 保存回答时的聚合依据，重新提问或打开详情时按当前有效成绩查询。
- **Skill 文件**　复用 `raw_content` 保存 Markdown 和 `name` 保存技能名。增量列 `source_filename` 只保存上传原名，历史记录用技能名生成展示文件名。

问答 Skill 采用 UTF-8 Markdown，上限 48 KiB。首次保存和同教师同名检查在同一事务中完成。

**数据边界**　附件只保存原始消息关联，会话和教师归属通过消息向上校验。两端共用 `sources` 保存回答当时的依据摘要，实时学情回原成绩查询。已有 Skill 名称用于标识技能，原始文件名用于上传记录。

普通与流式发送复用同一事务写入用户消息、附件绑定和最终回复。同一会话由 MySQL 8 会话行锁协调，已在生成时返回忙碌状态。消息唯一键和回复关联提供重试确认。断流后两端按会话和请求 ID 用 `GET /teaching-assistant/sessions/{session_id}/requests/{request_id}` 查询已提交回复，连接仍不可用时保留待发送内容。新增私有文档类别的列举、删除、重建索引和下载均按用途分流，`chat_attachment` 及试卷原件均由相应业务鉴权。旧客户端仍按原契约读取已产生的链接。

附件归属链为 `user_document.chat_message_id → chat_message.id → chat_conversation.id`，会话通过 `user_id` 鉴权。发送和读取均检查同一教师及会话。消息历史接口联查文档元数据，两端可恢复文件名、类型和预览入口。

现有 `exam_knowledge.py` 支持按卷名、题号和已结构化题干定位。语义召回复用 Milvus `teacher_documents`，通过 `EXAM_QUESTION_VECTOR_SEARCH=1` 启用。`server/scripts/reconcile_exam_question_index.py` 默认预览，按指定教师分页。按题号和内容版本生成 `chunk_id`，补齐缺失向量后再清理失效或重复片段。普通文档检索排除题目片段，批改召回回 SQL 核对权限、当前题干版本及有效成绩。确认、重批和撤回直接通过 SQL 生效。新增纸卷原件可复用 `user_document.parsed_text` 提供题干和选项文案。已有结构化题干优先，原件候选须与本卷题号和选项字母一致。同号文本冲突时使用已有题目数据或留空，移除原件后失效。只从有效成绩读取答案和统计。已上传且未解析的历史原件在重新上传同一文件时可补取，存量批量补录及真实数据对账待验收。

跨端续聊可直接使用会话和消息原表。工作区已有 `0017`、`0019`、`0020` 增量迁移文件，与试卷方案的迁移交错在同一主库链上，需按依赖顺序部署。表中四项增量均可空。兼容后端与两个客户端在目标库结构就绪后部署，历史行保留 `NULL`，兼容旧消息和链接，无需批量回填。当前主库 Alembic 旧链缺少 `0012` revision，发布前先核验环境上的迁移头和实际表结构，在可丢弃 MySQL 验证 upgrade/downgrade、多条 `NULL`、并发重试及历史读取。[已知迁移链问题](../../../.harness/changes/repository-layout-20261121/summary.md)

模型和索引依据。[会话与消息](../../../server/app/models/chat.py) · [用户文档](../../../server/app/models/stats.py) · [Skill](../../../server/app/models/agent_skill.py) · [试卷和提交](../../../server/app/models/exam_models.py) · [向量集合](../../../server/app/services/embedding_service.py)

**跨卷定位与澄清**　比较问题可提及两份及以上有权访问的试卷。共用检索服务按完整卷名或可区分的简称定位，支持同一题号比较，也支持在各卷名后分别指定题号。各卷独立计算有效答卷、正确率和典型错选，并返回各自来源。题号匹配多个候选且当前没有附件依据时，普通和流式问答直接返回确认范围的问题，历史照常保存。教师下一轮仅回复卷名时，从同一会话继承上一轮题号。未明确区分的同名候选仍需补充线索。

**近期批改和空态**　「最近」「近期」在没有指定卷名时，以当前教师可访问的试卷为范围，按各卷最新有效成绩时间倒序选取最多五份。待复核、撤回、被替换和缺少有效身份的记录均不参与选卷或统计。网页小 e 主页面和 H5 共用 `GET /exam-knowledge/availability`，只有服务端明确返回无有效成绩时才展示「暂无历史批改资料」。空态保留提问和附件入口，可从「去试卷」进入试卷列表。

**日期范围**　支持单日、连续起止日期和「昨天」「上周」「本月」「最近 7 天」等相对日期。两端按北京时间的日界换算 UTC 区间，先确定当前有效成绩，再按该成绩的有效更新时间筛选。可只追问新日期，沿用当前卷名及题号。引用历史保存绝对起止日期，并通过 `date_from`、`date_to` 传给原成绩统计 API。单题和整卷详情读取同一范围，旧引用维持原跳转。教师一次提供多个不连续的日期范围时，助手先请教师确定一个范围。数据库使用原时间字段和来源 JSON，无新增表或列。

### 页面到数据库的联调路径

下表的小 e 路径相对于 `/api/v1/teaching-assistant`。共用鉴权和分页参数。消息历史通过 `latest=true` 读取最新一页，通过 `next_before_id` 回看。H5 会话 URL 为 `/?session=<会话ID>`，网页端为 `/teaching-assistant/<会话ID>`。

| 两端操作 | 共享请求与服务入口 | 数据验证 |
| --- | --- | --- |
| H5 发送，网页打开同一聊天并追问 | `GET /sessions`、`POST /sessions`、`GET /sessions/{session_id}/messages`、`POST /chat/stream`。教学助手路由进入 `teaching_assistant_service.py` | 两端返回相同会话和已提交消息 ID，续问使用同一摘要和历史 |
| 加附件，断流后恢复或重试 | `POST /upload`、`GET /attachments/{attachment_id}`、`GET /sessions/{session_id}/requests/{request_id}`。由 `chat_attachments.py` 和 `chat_requests.py` 处理 | 每个附件关联一条用户消息，同一请求最多提交一条最终回复。未发出的文字和已上传引用可在当前端同一标签页恢复 |
| 无选卷控件，按题干或问题寻找已批过的试卷 | 流式问答进入 `exam_knowledge.py`，来源详情调用 `GET /api/v1/teacher/exam/{exam_id}/grading-knowledge` | 向量候选回查 SQL 属主和当前题目，答对、答错的口径使用正式有效提交。重批后的统计无需同步另一份成绩 |
| 侧栏设置上传 Skill，网页查看 | `POST /skills/upload` 和 `GET /skills`，复用 `agent_skill.py` | 以同一教师读取同一条 `agent_skill` 记录和原始文件名，上传后的启用状态按既有契约处理 |
