# H5 试卷功能开发方案

**目标**　让教师在手机上用已有账号创建试卷、配置评分、拍摄指定的固定答题卡、复核并查看批改记录。网页端与 H5 共用试卷、成绩和批改规则。

**架构**　沿用现有教师试卷 API、`ExamService`、答题卡 OMR 与逐题判分。H5 适配上传、取景和复核页面；固定版式适配、成绩确认、重批和记录查询沉到同一后端，由网页端与 H5 共同使用。

**依据**　[PRD v0.6](../../../product/prd/批卷H5端-PRD.md) · [Pencil 设计稿](../../../product/design/H5design.pen) · [问答助手开发方案](./2026-11-22-H5首页问答助手开发方案.md) · [现有扫码批改审计](../../../.harness/changes/answer-sheet-scan-optimization-20260921/summary.md)

Web 与 H5 共同读写主库，新增业务表为 0。试卷、评分模板、上传文件、扫描尝试、当前成绩和批改历史均使用已有表。

**确认事务**　锁定试卷和扫描记录，核验版式、评分配置与考号，查询并锁定当前成绩，按预览时的 `grade_version` 校验覆盖操作。提交新成绩时同步更新扫描状态、原扫描的替换状态、批改日志和现有错题记录。唯一键竞争返回版本冲突或既有回执。历史有效版本通过扫描记录与日志定位。正式确认沿用 `grading_status='teacher_reviewed'`，固定卡撤回将成绩改为 `paper_withdrawn` 并递增版本，保留身份唯一键、原图和历史，重新确认更新同一成绩行。待复核放弃改为 `discarded`，原因和复核版本写入扫描行现有 `grading_result`。无其余待复核或正式成绩时，评分配置可继续编辑。记录页以扫描尝试及对应的有效成绩、日志汇总。两个客户端与问答统计共用有效成绩查询，按卷兼容已核实的历史状态。

**关联关系**　`user_document.exam_id`、`exam_scan_record.exam_id` 和 `exam_submission.exam_id` 均指向 `teacher_exam.id`。当前成绩通过 `scan_record_id` 指向确认所用扫描，日志通过 `submission_id` 关联同一成绩并在 `detail` 引用历史扫描。草稿及记录沿用 `/api/v1/teacher/exam` 的 `/paper-drafts`、`/{exam_id}/paper-draft`、`/{exam_id}/sources`、`/{exam_id}/grading-records` 入口。

**草稿创建重试**　两端共用编辑器为首次保存或上传原件前建卷生成 `request_id`。服务端锁定现有教师账号行，在同一教师的 `teacher_exam.answer_sheet_config.paper_create` 中查找或写入请求 ID、请求摘要及创建版本。同请求同内容返回原试卷，内容不同返回 409。创建响应未知时，当前浏览器标签页按教师和端保存原请求与正在编辑的表单，刷新后可继续重试。先按原请求取回草稿，后续修改再按创建版本更新。其他端已修改时沿用草稿版本冲突规则。已取得试卷 ID 后刷新，直接打开该试卷并读取已保存原件，未上传的文件需要重选。放弃修改或主动退出会清除本地恢复信息。旧调用省略请求 ID 时维持原创建行为。该流程无需增列或迁移。

**迁移与存量**　先核对主库实际结构、MySQL 版本和迁移头。当前主库旧链缺少 `0012` revision。原件、模板停用和固定卡批改迁移文件 `0016`、`0018`、`0021` 已在工作区，与问答方案的迁移按同一主库依赖链部署。隔离 SQLite 已验证 `0021` 的升级、存量行、前导零、唯一约束和回退。实际 MySQL 升级待迁移头与结构核验后验证。校验干净库与存量样本的升级及回退、可空字段、生成列和并发唯一性。存量试卷切换前，检查缺考号、同卷重复考号和版式匹配。同卷历史重复数据进入人工核对，保留历史记录。纸质有效份数、待复核份数及按题统计从提交及扫描记录查询。日志只保存追溯所需的变化，题目索引按问答方案刷新。[已知迁移链问题](../../../.harness/changes/repository-layout-20261121/summary.md)

### 字段复用与写入边界

- **评分结构与标准答案**　模板维护可复用的题数、选项和分值。应用时将逐题配置及本卷独立设置的答案写入 `teacher_exam.questions`。模板更新只影响后续应用，旧卷按本卷快照判分。固定卡坐标集中登记在服务端目录，共用同版固定卡的试卷只记录版式 ID 和版本。
- **扫描与成绩**　上传或重拍产生扫描尝试，识别原值和待复核内容留在 `exam_scan_record`。教师确认后，同一身份的当前结果写入 `exam_submission`。重批更新同一成绩行，旧结果通过 `exam_grading_log.detail` 和原扫描记录追溯。
- **批改状态与统计**　纸质状态由 `exam_result_state.py` 根据版式、逐题答案、复核活动和结束标记推导。成绩总数、待复核数、正确率与选项分布查询原表。无班级唯一键使用从既有考号派生的生成列，业务仍写入原考号字段。
- **文件归属**　试卷原件复用 `user_document`，答题卡照片沿用 `exam_scan_record.scan_image_url` 引用。文件按各自业务的归属链鉴权。原件解析复用文档提取器，题干匹配由 `server/app/services/exam_source_text.py` 按题号和选项处理。解析与原件移除无需更新试卷题目、标准答案或成绩。共享主库的六个增量迁移按[问答方案的迁移顺序](./2026-11-22-H5首页问答助手开发方案.md#与试卷方案共用的迁移顺序)执行。

### 页面到数据库的联调路径

两端通过 `client/src/api/teacher.ts` 进入 `server/app/api/v1/exam.py`。下表路径相对于 `/api/v1/teacher/exam`。

| 两端操作 | 共用请求与服务入口 | 数据验证 |
| --- | --- | --- |
| 网页建卷，H5 续编并上传原件 | `POST /paper-drafts`、`GET/PUT /{exam_id}/paper-draft`、`/{exam_id}/sources`，进入 `paper_draft.py` 和 `exam_sources.py` | 同一个试卷 ID、同一个有序原件列表。创建响应丢失时，用原请求 ID 取回草稿，原件更新无需复制试卷题目 |
| 应用模板、录入本卷答案，再编辑模板 | `GET /templates/list?paper_only=true`、`PUT /answer-sheet-templates/{template_id}`、`PUT /{exam_id}/paper-draft`，由 `exam.py` 与 `paper_draft.py` 校验 | 模板表存可复用结构，当前试卷沿用 `questions` 快照。修改模板后，旧卷的分值和答案仍可按原规则复核 |
| H5 拍照，网页查看待复核并确认 | `POST /{exam_id}/fixed-scan`、`GET /{exam_id}/fixed-reviews`、`POST /{exam_id}/fixed-reviews/{scan_id}/confirm`，进入 `fixed_paper_review.py` | 扫描与成绩均关联原试卷。重复请求返回原扫描或回执，确认前待复核记录与正式统计分开 |
| 任一端重批或撤回，另一端看记录与统计 | `/{exam_id}/grading-records` 及其重批和撤回操作，进入 `exam_records.py`、`fixed_paper_review.py`、`exam_result_state.py` | 两端读取同一条当前成绩和同一份版本日志。问答读取与记录页面相同的有效成绩集合 |

**固定卡联调入口**　前缀为 `/api/v1/teacher/exam/{exam_id}`。待复核列表使用 `GET /fixed-reviews`，详情和修正使用 `GET`、`PUT /fixed-reviews/{scan_id}`，提交使用 `POST /fixed-reviews/{scan_id}/confirm`。单题修正沿用 `answers` 保存单选或空白，用 `invalid_answers` 显式确认两个及以上实际填涂选项。原值从扫描记录保留，核定多涂写入既有作答字段并判零分。修正与确认均携带复核 `revision`，重批还携带原成绩 ID 与版本。试卷、扫描、成绩 ID 在 JSON 中沿用字符串输出。画板 25–29 对应复核和考号，30–34 对应记录，50–51、53–54、57、60 对应冲突和历史等状态。H5 和网页端已接入复核、确认、重批和原图预览。待复核原图走 `GET /fixed-reviews/{scan_id}/photo`，确认后的当前原图走 `GET /grading-records/{submission_id}/photo`。服务端从扫描记录定位同一文件，默认存于 `server/data/paper_scans`，部署可用 `PAPER_SCAN_DIR` 指到持久卷。两端通过 `GET/PUT /paper-grading-state` 结束和继续批改，后端锁定试卷行后核对复核队列、有效成绩和状态版本。试卷列表返回独立的 `paper_state`，原线上 `status` 保留。放弃使用 `POST /fixed-reviews/{scan_id}/discard`，已放弃列表使用 `GET /fixed-reviews?status=discarded`。撤回使用 `POST /grading-records/{submission_id}/withdraw`，需要当前成绩版本和原因。已结束的试卷须先开启补批再撤回。撤回与 SQL 错题移除同事务提交。两端通过 `POST /fixed-scan` 上传照片，携带请求 ID。识别成功返回待复核记录，失败可从历史操作查看原因和原图。正式识别需先登记版式，再用真机实物样张校准。

**固定卡预览**　H5 和网页端共用 `FixedCardGuide.tsx`。`GET /{exam_id}/fixed-card/reference` 核验教师与试卷归属，读取本卷绑定版式的 `reference.png`，通过 `X-Paper-Layout-Version` 提供版本。无可用样张时返回 204，显示 Pencil 画板 17 的示意图，预览入口保持禁用。这个入口不开放上传或生成答题卡，也不读取学生的扫描照片。

**并发冲突**　确认接口对复核版本或对应成绩已变化返回 HTTP 409，保留原 `detail` 并附 `error_code=paper_review_conflict`。两端共用 Pencil 画板 47 的冲突弹窗。点「刷新并核对」只重新读取当前复核和成绩，教师核对后再主动确认。试卷结束或配置变动等情况继续展示服务端原因。沿用既有复核和成绩版本，迁移无需增加字段。

**从成绩详情重批原卡**　Pencil 画板 31 中「重批这份答题卡」通过 `POST /{exam_id}/grading-records/{submission_id}/regrade` 发起，携带当前成绩版本和请求 ID。接口复用固定卡原图、识别原值和上次确认的填涂，生成或打开同一成绩版本的待复核草稿。在已有扫描结果 JSON 中登记原成绩及版本。教师可修正填涂，确认仍复用同一成绩版本校验和批改日志。试卷已结束时，先开启补批再操作。

**批改记录筛选**　H5 和网页端通过 `GET /{exam_id}/grading-records?include_scans=true` 查询已确认、待复核、识别失败和历史操作。确认后的成绩通过提交记录展示，待复核、识别失败及已放弃的答题卡通过扫描记录展示。后端统一按更新时间分页，可按考号、学生姓名和状态筛选。扫描行打开对应复核或扫描详情，返回时保留筛选条件。旧调用省略 `include_scans` 时继续查询试卷提交记录。沿用现有表和字段。

**试卷列表**　H5 使用现有 `GET /list`，传入 `grading_view=true`，按需追加 `search`、`paper_status` 和 `page`。列表按试卷、扫描及提交的最后更新时间排序，已确认与待复核数量从原表计算。纸质状态沿用试卷就绪判定，状态筛选以每批 100 份候选卷计算匹配总数并返回当前页。未传新参数的网页调用沿用原创建时间排序和线上状态筛选。返回列表恢复搜索及状态，清除条件后从第一页读取。复用已有字段。

**试卷详情与评分规则**　草稿详情的「题型分数模板」与「本卷答案」分别打开 `/exams/:examId/edit?step=template` 和 `?step=answers`。没有已应用模板时先进入模板步骤。开始批改后可在 H5 和网页端通过 `/exams/:examId/rules` 打开共用的 `client/src/shared/exams/PaperRules.tsx`，读取已有 `GET /{exam_id}/paper-draft` 返回的本卷模板快照、逐题选项、分值和标准答案。此页面只读，沿用现有接口及表结构。

## 2026-11-23 固定手写卡实现调研

基于 [PRD v0.6](../../../product/prd/批卷H5端-PRD.md) 和 [需求变更](../../../product/changes/2026-11-23-固定答题卡扫描与准考证号.md)。以下为拟实施方案。使用现场照片评估拍摄偏差，以正式发放的同版空白原件标定。当前两张参考的版式不同，正式考号格数及纸面坐标待核定。

### 定位与取景

1. 保留 `FixedCardCapture.tsx` 的共用相机、相册和识别入口。根据版式的取景宽高比显示引导框，覆盖姓名、考号、所有参与评分的填涂区及定位锚点。按视频实际尺寸和预览缩放方式核对边界，首版上传完整照片，避免预览裁剪切掉定位点。保留拍照确认、重拍及相册路径。[MDN 相机拍照示例](https://developer.mozilla.org/en-US/docs/Web/API/Media_Capture_and_Streams_API/Taking_still_photos)
2. 在 `fixed_card_layouts.py` 扩展版式 JSON。以空白原版的像素坐标登记取景范围、姓名区、按列排序的考号格、固定印刷特征和选项区域。沿用现有 ORB、RANSAC 单应变换与 `warpPerspective`。针对正式卡先评估黑色定位标记辅助定向和匹配；标记形状不唯一时，结合位置关系和印刷特征区校验。核对重投影误差、匹配点覆盖范围及姓名、考号和题区是否完整落在原图有效区域。保留反光、模糊、裁切、定位失败、异版的可区分状态。阈值以同版实拍校准。[OpenCV 特征匹配与单应变换](https://docs.opencv.org/4.13.0/d7/dff/tutorial_feature_homography.html)
3. 现有 `question_regions` 和填涂采样继续负责 OMR。保留原始选项、空白、多涂和低置信标记。调整 `paper_draft.py` 与共享编辑器，按卡面题号生成本卷评分映射，例如第 5 题之后可直接绑定第 21 题。用卡面实际选项校验模板，判分继续由服务端使用本卷快照。

### 手写考号路线

| 路线 | 实施与取舍 |
| --- | --- |
| Tesseract 单格 OCR | 裁格后仅送单个字符，使用单字符模式和数字白名单，作为低成本对照。结果来自真实样张对比，现有文档 OCR 的效果无法代表考号识别率。[Tesseract 单字符与字符白名单说明](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html) |
| 本地数字分类器 | 推荐作为正式候选。复用矫正图及空白底板处理格线，批量分类 `0–9`，保留空白、跨格、笔迹分割异常及低置信拒识。按写字人拆分标定和验收样本，衡量整串准确率和误接受率。实际模型与阈值由样张比较决定。 |
| 通用手写 OCR 或条码 | 通用手写 OCR 作为对照；官方手写能力指标不能直接外推到本校纸卡。条码仅在编码规则核定后作为辅助核对，冲突交教师复核。保留姓名区及考号裁图供授权教师核对，无需把姓名 OCR 加入首版身份判定。[PaddleOCR 手写识别文档](https://www.paddleocr.ai/v3.5.0/en/version3.x/algorithm/PP-OCRv5/PP-OCRv5.html) |

仅当恰好得到版式规定的 N 个数字且各位置均通过校验时，生成候选字符串。任何格外续写或识别异常转复核。前后端校验均以版式 N 为准，人工纠正和确认共用规则。

### 后端复用与存储

- `exam_scan_record` 继续保存原图引用、候选考号和 OMR 原值。逐格识别、异常位、版式版本、考号人工修正及确认所需状态放入现有 `grading_result`。裁图可在鉴权后按版式从私有原图生成。测试样张使用合成或已按授权脱敏的材料。
- 复用 `exam_submission.exam_number` 保存确认后的定长文本，`student_id` 用于授权花名册关联。调整 `fixed_paper_review.py` 的固定手写卡查重顺序，先按本卷考号锁定已有成绩，再核对学生关联；遇到同号不同学生或同学生不同号时进入冲突复核，避免静默覆盖。
- 继续使用扫描请求 ID、成绩版本和 `exam_grading_log`。并发唯一性须由数据库约束兜底。先审计已有关联和未关联成绩中的重复数据，再决定是否扩展现有虚拟生成列，把参与固定卡确认的成绩纳入同一试卷考号唯一键。若既有 `grade_version` 无法安全区分适用记录，再评估最小的流程区分字段。旧网页扫码路径保留既有规则，已纳入新流程的试卷服从新版确认规则。无新增业务表。

### 验收顺序

先取得正式空白卡和同版填写样张，核对页别、格数、印刷题号、每题选项、条码语义和照片裁切边界。然后比较手写方案，记录定位成功率、逐格及整串准确率、误接受率、需复核比例和处理时延，用独立样张核对前导零、格外续写、阴影、透视、跨格、擦改和异版。最后联调两端及 MySQL 并发确认，检查花名册关联与无班级场景的同卷同号、跨卷同号和重批。正式阈值及识别效果待实测。

## 固定手写卡技术开发方案

### 交付范围

网页端与 H5 共用固定卡入口。给本卷绑定一个已发布版式，从拍照或选图进入定位、矫正、逐格考号识别和选择题判分预览，经教师核对后写入成绩。已有旧网页扫码入口按原契约运行。正式样张未定前可用合成版式实现并验收通用链路，正式版式的格数、坐标和阈值留待标定。

### 版式与评分配置

| 配置 | 契约 |
| --- | --- |
| 版式制品 | 沿用 `<layout_id>/<version>/layout.json` 与同尺寸 `reference.png`。已绑定的版本只读；坐标或识别规则变更发布新版本。空白参考图、印刷锚点和识别区域均使用参考图坐标。 |
| 考号 | 旧版沿用 `exam_number_columns`。新手写版式增加 `exam_number_cells`，由左至右列出每位的矩形，格数以数组长度为准。登记时校验非空、不重叠及在参考图内。姓名区与格右侧检查区域分别配置。 |
| 取景 | 版式提供归一化取景范围及必拍区域。使用底部角标时引导整页拍入。预览按视频实际宽高和缩放换算，引导框不参与上传裁剪。后端独立检查原图是否包含关键区域。 |
| 判分 | 每卷复用 `teacher_exam.questions` 保存实际卡面题号、选项、分值和本卷答案。通用模板应用时建立“模板项 → 卡面题号”映射，支持跳号和部分题位。一题只绑定一次。读取、保存、复核、历史和问答均以保存的 `question_number` 为准。旧草稿已保存的题号沿用原值。 |

### 扫描处理与人工兜底

1. **拍摄**　共享的 `FixedCardCapture` 在 HTTPS 下打开后置相机，取景框覆盖姓名区、完整准考证号、选择题区及版式所需定位标记。预览框按实际视频像素换算，提交整张拍摄静帧。授权失败或无相机时可从相册选图。退出、切换页面和重开相机时释放摄像头。[Media Capture and Streams 规范](https://w3c.github.io/mediacapture-main/#dom-mediadevices-getusermedia)
2. **定位与矫正**　服务端统一处理方向与清晰度，先匹配本卷版式的印刷锚点，再用现有 ORB 特征和 RANSAC 单应矩阵将照片映射到参考图。保留单独的有效像素掩膜，检查姓名区、每个考号格及所有已绑定选项是否完整可读，防止透视补出的白色被当成漏填。定位不足或必拍区域缺失提示重拍。只有定位可信且印刷区域确有差异时返回版式不符。[OpenCV 特征匹配与单应变换](https://docs.opencv.org/4.8.0/d1/de0/tutorial_py_feature_homography.html)
3. **考号**　从矫正图按格裁切，去印刷线后从左往右输出逐位候选。先实现按格人工录入和服务端定长校验，再以真实同版样张评估单格数字分类器，可用 ONNX Runtime CPU 批量推理。空格、跨格、低置信或格外续写需要复核，保留原格顺序。确认值必须是恰好等于格数的 ASCII 数字字符串，保留前导零，条码仅供比对。使用完整长号或条码的历史记录仅在核对后关联。[ONNX Runtime Python 文档](https://onnxruntime.ai/docs/get-started/with-python.html)
4. **填涂与判分**　按参考图与矫正图的选项区域灰度差判断填涂。保留正常、明确空白、弱填和多涂状态。弱填和多涂交由教师核对，明确空白按该题未答处理。识别和教师修正完成后调用共用的 `grade_choice_answers`，按实际卡面题号读取本卷答案和分值，未绑定题位不计分。预览不写正式成绩。
5. **确认与回显**　复核页展示原图、身份区、考号及异常题。记录确认前再次校验版式、复核版本和考号。确认后两端从同一成绩数据读取记录，问答沿用已有的有效成绩查询。

### 代码实施顺序

| 步骤 | 主要目录 | 完成条件 |
| --- | --- | --- |

### 接口与状态

试卷接口统一在 `/api/v1/teacher/exam/{exam_id}` 下，使用现有教师鉴权和试卷归属校验。

- 复用 `GET /paper-grading-state` 返回手写版式的 `capture_aspect_ratio`。两端用参考图比例和视频实际可见区域计算整卡取景框。服务端始终按本卷绑定版式识别。现有 `GET /fixed-card/reference` 继续返回空白参考原件。
- `POST /fixed-scan` 继续上传照片和请求 ID，原回执保留 `review`、`retake`、`layout_mismatch` 及 `scan_id`，拟加可选 `reason_code`。同一请求重试取回同一扫描结果；重新拍摄使用新请求 ID。模糊、裁切或定位不可靠走重拍。卡面有效但考号或填涂可疑走待复核。待复核和失败扫描均不计入正式成绩。
- `GET /fixed-reviews/{scan_id}` 拟补版式规定格数及按位异常。原图继续走鉴权图片接口，身份区裁图可在鉴权后按需读取。 `PUT /fixed-reviews/{scan_id}` 保存修正；允许暂存未填完整的考号，只有严格匹配版式长度和数字格式、且全部异常已核对时才允许确认。
- `POST /fixed-reviews/{scan_id}/confirm` 沿用复核版本、上一成绩 ID 和成绩版本。重复考号先返回原成绩供对照，显式确认重批后更新。扫描重放返回原确认回执，复核或成绩版本已变化时返回 409，前端重新读取后让教师核对。浏览器中的长整型 ID 保持字符串。

### 数据库与并发

1. 原图、原始填涂、逐格识别结果和复核信息沿用 `exam_scan_record` 及 `grading_result`。正式考号沿用 `exam_submission.exam_number`。 `student_id` 继续关联花名册；姓名和条码只用于核对。日志保留变更前后值，扫描原值保持可追溯。
2. 部署前只读检查同卷同号、同卷同学生不同号、空号及历史固定卡身份标记。若现有 `grade_version > 0` 可安全区分需要纳入约束的固定卡成绩，优先新建迁移扩展现有考号生成列的适用范围，复用 `(exam_id, 生成列)` 唯一约束，使有班和无班记录都参与查重。确认成绩与撤回的原记录继续占用该身份，补批更新同一行。若审计发现标记混用或重复，先核定迁移规则；仅在确有需要时增加流程区分字段。考号不再增加实体副本，无新增业务表。
3. 确认事务按已有顺序锁定试卷、扫描及当前成绩，按本卷考号查重后校验花名册关联。出现同号不同学生、同学生不同号或历史重复时进入人工核对。有效成绩、扫描状态、批改日志及错题变更同事务提交，数据库唯一约束兜底并发写入。可重试的唯一键冲突转换为同一回执或 409。

### 实施验收与启用

- **后端**　扩展 `test_fixed_paper_review.py`、`test_paper_draft.py`，覆盖倒转、透视、裁切、反光、异版、跳号、空格、前导零、格外续写、条码冲突、留档及旧版兼容。先以测试替身验证手写识别协议，再用独立的同版脱敏样张核对整串正确率和复核率。概率阈值在评审样张结果后确定。
- **两端**　沿 Pencil 画板 19–29、45、47、50、51、53、60 核对取景、重拍、识别结果、考号复核、重复成绩及并发冲突。真机用 HTTPS 验证 iOS 和 Android 的后置相机、相册、权限和摄像头释放。老师能够在复核页同时看到姓名区、考号格和疑似异常。
- **数据库与发布**　按 `task verify`、两端构建和 `task unit` 验证实现。目标 MySQL 先检查迁移头与重复数据，在可丢弃库预演升级和回退，再测两个客户端并发确认同号。应用兼容版本就绪后启用新登记版式。回退时停用新版式入口并保留原图、已确认成绩和历史。

本方案的开工输入为正式同版空白卡、脱敏填写样张及页别、格数、条码规则。照片与电子参考的版式差异尚未核定，正式登记和上线验收在取得这些材料后执行。

### 两张参考图的验证安排

| 输入 | 验证用途 | 判定依据 |
| --- | --- | --- |

## 固定答题卡登记与标定

以下为现有配置及已实现的填涂考号登记方式。正式手写卡按上节扩展。

- 将正式空白答题卡的平整、正视图保存为 `reference.png`，最长边不超过 2400 像素。与同版 `layout.json` 一起放入 `PAPER_FIXED_CARD_LAYOUT_DIR/<版式标识>/<版本>/`。默认目录为 `server/data/fixed_card_layouts`，部署时由服务端读取。
- `layout.json` 使用参考图片坐标。每个区域用 `cx, cy, w, h` 表示中心与宽高。`question_regions` 按题号映射到选项字母及对应区域。可选的 `exam_number_columns` 按从左到右的考号位排列，每一位应完整列出 0–9 的填涂区。省略时由教师在复核录入考号。至少标记两个不会被填写且能区分版式的印刷特征区 `identity_regions`。使用实物样张核定 `fill_threshold` 与 `faint_threshold`。
- 将登记版本指定为 `PAPER_FIXED_CARD_DEFAULT_LAYOUT=<版式标识>/<版本>`。首次保存未绑定版式的纸质草稿时写入配置 JSON。已有绑定保留原版本。新版式登记使用新的版本目录。
- 手写版式配置 `exam_number_cells` 和 `name_region`。可另配位于最后一格右侧的 `exam_number_overflow_region`。完成同版实拍标定后，将 `digits.onnx` 放在版式版本目录内，并配置 `digit_model_min_confidence`。推理复用现有 OpenCV DNN，模型输入为动态批量 `float32[N,1,28,28]`，范围为 0–1，黑底白笔迹，等比例缩放至最长边 20 后居中，输出为 `float32[N,10]` logits，索引对应 0–9。任一格缺失或低置信，或格外检测到笔迹时，保留逐格候选，由教师核对后填入最终考号。未配置分类器时沿用人工录入。
- 正式验收使用需求方提供的空白原版和已填写样张，覆盖正确填涂、空白、多涂、擦改、前导零、异版、倾斜和光照。OpenCV 以登记参考图定位并比对印刷区，再复用已有区域灰度采样。识别成功后由教师核对并确认成绩。

## 依赖与上线顺序

先接通试卷与模板，再验证固定答题卡样张。之后同时联调 Web 和 H5 的预览、确认、重批及历史记录。正式上线前需取得空白原版和填写样张，确定题位、选项及考号规则，并实测识别率、确认耗时和错判复核。问答功能可并行使用合成批改数据开发，最终以共用成绩数据源验收。
