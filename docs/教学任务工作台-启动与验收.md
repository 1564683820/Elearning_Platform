# 教学任务工作台：启动与验收

业务链路为“最近两次考试中的薄弱点 → 教材证据 → 定向教案与选择题 → 教师修订与审核 → 发布到已有试卷模块”。Web 地址为 `/Elearning/teaching-tasks`，侧栏入口为“教学任务”。新增接口不改变小程序已有学生考试、提交和批改接口；发布产物为 `teacher_exam`。

## 当前交付边界

代码已提供六步 LangGraph 编排、MySQL 业务检查点、Redis Streams 派发、事务 outbox、租约心跳、有限重试、取消、版本审核与幂等发布，以及 Web 操作页面。独立回归使用真实 SQLite 事务和确定性外部工具；浏览器回归使用明确标记的合成 HTTP 数据。

真实 MySQL/Redis/Milvus/模型链路尚未验收。用户选择先完成代码与独立验证，因此未创建数据库、未执行在线迁移、未写入合成数据、未调用付费模型。50 条检索样本和 20 个任务场景已固定，但模型质量、教师采纳率、费用和优化前后对比仍没有实测值。录屏应在真实链路通过后制作。

## 隔离环境

使用 Codex bundled Python 创建的项目虚拟环境 `.venv`，不要重新使用出现 `0xc0000022` 的旧解释器。

从仓库根目录运行 `task setup` 安装依赖。`server/requirements.txt` 是安装真源；本次 LangGraph 依赖使用 Pydantic 2.14.3，FastAPI 固定到 0.115.14，已经做应用导入和原有回归检查。可选浏览器回归依赖见 `server/requirements-test.txt`。

将 `server/teaching.env.example` 中需要的配置写入 Git 已忽略的 `server/.env`。填入本机 MySQL 账号、口令和有效 LLM/Embedding 凭据，并分别配置 `JWT_SECRET`、`SECRET_KEY` 和 `AES_SECRET_KEY`。不要将凭据发到聊天或加入 Git。

固定使用以下隔离目标：

| 服务 | 开发目标 |
| --- | --- |
| MySQL 主库 | `elearning_agent_dev` |
| MySQL 单词库 | `elearning_agent_words_dev` |
| Redis | `REDIS_PREFIX=elearning_agent_dev:` |
| Milvus | `MILVUS_DATABASE=elearning_agent_demo`，先创建该数据库 |

从 Windows 服务管理器启动 MySQL80。启动本机 Redis 和 Milvus 及其依赖，确认 3306、6379、19530 端口。当前会话曾读取到 MySQL80 已停止，且进程没有 Windows 服务启动权限。

以下命令只用于上述两个空库，不适用于旧数据库。所有命令从 `E:\Elearning` 执行：

```powershell
# 仅创建两个固定命名的空库；发现已有业务表就拒绝，不会删除数据
.\.venv\Scripts\python.exe server/scripts/create_teaching_databases.py

# 从仓库根目录运行
.\.venv\Scripts\python.exe -m alembic -c server/database/alembic-agent.ini upgrade head

# 独立设置 TEACHING_DEMO_PASSWORD 环境变量（至少12字符，不放进命令历史）后执行
.\.venv\Scripts\python.exe server/scripts/seed_teaching_demo.py

# 以下命令会调用配置的 Embedding API 并写入隔离 Milvus 数据库
.\.venv\Scripts\python.exe server/scripts/seed_teaching_demo.py --index

.\harness.ps1 check-teaching
```

基线冻结 48 张主库表和 6 张单词库表，使用独立 Alembic 链，不依赖旧链中缺失的 `0012`。已验证 `upgrade head --sql` 能生成离线 SQL，不能据此声称在线迁移成功。MySQL DDL 不是事务；基线仅允许空库，失败后先核对已执行语句，不要直接重新初始化或覆盖。回滚会删除数据，因此没有自动破坏性 downgrade。旧开发库已经执行过 0014 的情况，另有追加脚本 `server/database/alembic/versions/0015_teaching_workflow.sql`，未在本次会话执行。

合成数据含 2 位教师、2 个互相隔离的班级、4 位学生、4 次历史考试、8 份已批改作答、2 份自编分页面材料。账号为 `demo_teacher_1`、`demo_teacher_2` 和 `demo_student_1` 至 `demo_student_4`，密码采用执行 seed 时设置的私有值。重复 seed 会拒绝覆盖。教材使用换页符保存页码，旧资料没有页码时明确显示“原文未保留页码”，不会猜测页号。

分别在三个终端运行：

```powershell
.\harness.ps1 dev-backend
.\harness.ps1 dev-worker
.\harness.ps1 dev-web
```

`check-teaching` 只检查配置存在、数据库 SELECT 1 和端口可达，不代表 Redis 认证、Milvus Schema 或模型密钥已经通过功能验收。Web 默认 URL 为 `http://127.0.0.1:5173/Elearning/`。

## 操作与接口

教师登录后，先进入班级与文档页面检查合成数据。创建任务，选择本班级，默认生成 20 分钟教案和 10 道题。点击“开始备课”，查看统计与教材证据。生成后可修改教案、题目、答案、解析、分值。保存修改增加内容版本并清除旧审核；必须审核当前版本才能发布。发布后在“试卷”页面和对应学生考试入口继续使用原有考试流程。

| 接口（前缀 `/api/v1/teaching-tasks`） | 行为 |
| --- | --- |
| `POST /`、`GET /`、`GET /{id}` | 创建、分页列表、详情；ID 字符串响应 |
| `POST /{id}/run` | 登记队列与 outbox，同一事务提交 |
| `POST /{id}/retry` | 失败从成功检查点继续；缺资料时重新分析与检索 |
| `POST /{id}/cancel` | 作废 Worker 租约，阻止旧结果回写 |
| `PUT /{id}/artifact` | `{version, artifact}`，编辑时进行结构和业务校验 |
| `POST /{id}/approve` | `{version}`，审核当前版本 |
| `POST /{id}/publish` | `{version}`，锁定任务行后复用现有试卷发布服务 |
| `GET /{id}/events` | 带 Authorization 请求头的 SSE；断开可重新读取持久快照 |

无权限或班级授权撤销返回 404；不允许的状态操作、旧版本审核/发布返回 409；不合法内容返回 422。每次任务读取、操作及每个执行边界检查班级权限，检索前构造 SQL 允许的文档 ID 集合，再传递到 Milvus 过滤。命中必须还能匹配当前文档原文，过期和跨域片段不能作为证据。

## 恢复机制及限制

LangGraph 负责六个节点的依赖与修正循环。持久化采用应用自己的 SQL 节点检查点，审核等待由业务状态表达，**没有接入 LangGraph 原生 Checkpointer 或 interrupt/resume API**。这是当前实现相对初始方案的差异；不应在简历中写成已经实现原生图检查点。

每个成功节点完成后保存状态、引用、统计和调用记录；重试会跳过成功节点。LLM 校验最多进行两轮自动修正，持续失败等待教师输入。暂时性网络错误、429 和指定 5xx 最多自动重试两次。SQL outbox 在 Redis 不可达时保留派发意图；Redis 恢复后重新派发。Worker 每20秒续约90秒租约，SQL 租约过期扫描和 Streams pending reclaim 恢复失效执行。外部模型请求可能在保存前因进程终止而重复计费；不宣称第三方 API exactly-once。

发布时使用 MySQL 任务行锁，审核版本与发布版本绑定，重复请求返回同一个试卷 ID。SQLite 回归证明顺序重复请求的行为，不能证明 MySQL 并发锁的正确性；真实双请求、kill Worker、Redis 重启和 API 重启仍需联调。

目前生成题型限定四选一；历史多级阅读/完形子题统计未做展开。原文匹配与页码校验保证来源可追踪，不等同于知识点相关性或教学质量；无关检索仍可能被返回，需要利用固定检索集测量并改进拒答阈值。费用没有定价配置时保持 null，不估算为0。

## 验证与评测

```powershell
.\harness.ps1 verify
.\harness.ps1 unit
.\harness.ps1 build

# 已有 Vite 开发服务时，运行合成 HTTP fixture 的浏览器交互检查
.\.venv\Scripts\python.exe server/tests/browser_teaching_tasks.py

# 真实服务与材料索引就绪后运行，会调用 Embedding API
.\.venv\Scripts\python.exe server/evaluations/teaching/run_rag.py
```

浏览器脚本依赖本机 Edge，检查创建、SSE、编辑审核约束、发布、刷新与平板宽度，截图保存到忽略跟踪的 `server/output/teaching-browser/`。它不代替后端集成验收。

检索集 `rag_cases.json` 包含40条有证据问题、5条无资料问题、5条跨班级访问问题。任务集 `task_cases.json` 固定20个业务、权限与恢复场景，注明自动回归映射和需要人工教学评价的样本。`run_rag.py` 输出样本哈希、版本、检索命中与耗时；未测量的质量、费用、基线对比字段保留 null。任务集尚未提供全自动在线批跑器，教学采纳率需要教师逐条评审。

真实验收顺序：登录 → 建班 → 上传并检索自编材料 → 学生提交 → 批改保存 → 创建并运行教学任务 → 审核修订 → 重复发布 → 学生看到练习。之后进行跨教师读取、授权撤销、两实例并发发布、断连与进程终止恢复，再记录模型质量与成本。
