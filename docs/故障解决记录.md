# 故障解决记录

每次解决问题后，在这里追加日期、现象、确认的根因、修复方法和验证结果。尚未查明的原因单独标注。

## 2026-11-21 · Windows 后端连接 Docker Milvus 失败

**状态：已恢复。**

### 现象

FastAPI 启动时访问 `127.0.0.1:19530` 失败。Docker Desktop 显示 Milvus 容器正在运行，但健康检查一直处于 `starting`，重启次数持续增加。日志里的 `pkg_resources` 弃用提示与本次故障无关。

### 排查与根因

1. `docker logs` 显示 Milvus 启动时报 `failed to create etcd client: context deadline exceeded`。
2. `etcdctl endpoint health` 确认 etcd 自身健康。`docker inspect` 显示 etcd 在 `backend_default`，但 Milvus 的实际网络列表 `NetworkSettings.Networks` 为空。Milvus 因而无法通过 `milvus-etcd:2379` 访问 etcd，启动失败并反复重启。
3. Compose 已配置 `19530:19530`，但故障期间 `docker port` 没有返回有效映射，Windows 上也没有监听 `19530`。截图中的 `18000` 属于 Attu 管理界面。

没有查明 Milvus 最初脱离 Docker 网络的原因。

### 修复与验证

确认上述网络归属后，将现有 Milvus 容器接回原 Compose 网络。`--alias milvus` 恢复同网络容器使用的服务名。

```powershell
docker network connect --alias milvus backend_default elearn-milvus
```

修复后，Docker 显示 `healthy`，`http://127.0.0.1:19091/healthz` 返回 `OK`，`docker port` 显示宿主机 `19530` 的映射。使用项目的 `.venv` 和实际后端配置连接 Milvus，成功列出 7 个集合。

### 下次怎么查

```powershell
docker ps --filter name=elearn-milvus
docker logs --tail 100 elearn-milvus
docker network inspect backend_default
docker port elearn-milvus 19530/tcp
```

分别验证 **宿主机 → Milvus** 的端口转发和 **Milvus → etcd** 的容器间连接。`running` 表示容器进程正在运行，`healthy` 表示已通过配置的健康检查。

## 2026-11-21 · Milvus 已连接，但后端索引初始化失败

**状态：已修复。**

日志先出现 `Created new connection`，随后在检查 7 个集合时抛出 `TypeError: object of type 'IndexParams' has no len()`。这定位到连接建立后的索引初始化阶段。现有异常包装把连接和初始化失败都显示为“Milvus 连接失败”。

项目安装的 `pymilvus==2.4.0` 中，`IndexParams` 可以迭代，但没有实现 `__len__`。`EmbeddingService._ensure_indexes` 调用 `len(index_params)`，无论是否存在待创建索引都会报错。修复后，代码在加入待创建索引时记录标记，有待创建项才调用 SDK 的 `create_index`。[索引初始化实现](../server/app/services/embedding_service.py#L446)

使用项目 `.venv` 先复现了两个分支的错误，再验证索引齐全时跳过创建，缺索引时仅提交缺失项。`harness.ps1 unit` 共 101 项通过，`test` 和 `lint` 通过。用实际配置连接本机 Milvus 并执行集合初始化检查，7 个集合的预期索引齐全且均为 `Loaded`。复验禁止创建或删除集合与索引，未执行完整 FastAPI 重启。

## 2026-11-21 · 复用旧库后网页报 401，历史教材与文档预览报 404

**登录失效。** Kimi WebBridge 观察到文档、班级和教学任务返回 401，浏览器仍保留过期 JWT 和用户信息。直接访问本机 FastAPI 的 `/health` 返回 200，未登录的文档请求返回 401。Web 现在会在当前会话的 Bearer 请求被拒绝时清理会话并进入登录页，重新登录后回到原页面。文档列表用页面内错误状态代替阻塞弹窗。

**历史教材图片。** 旧库保存的 `/uploads/textbook/…` URL 指向 83 张仅存在于旧项目的 PNG。网页代理原先返回 404。按数据库引用复制图片到当前服务使用的 `backend/uploads/textbook`，只创建缺失文件。逐条通过代理执行 HEAD，83 条都返回 200。重新部署时需把对应运行时图片放进实际的 `UPLOADS_DIR`。

**历史文档预览。** 文档路由把十进制字符串 ID 转成 JavaScript `number`，超过安全整数范围时会舍入。用原始 ID 请求返回 200，用舍入后的 ID 请求返回 404。预览现在将 ID 按字符串传给后端，并使用 Authorization 请求头。发布试卷时也保留所选班级 ID 的字符串表示。

真实浏览器重新登录后，文档、班级、试卷、PPT、教学任务、教学助手列表均返回 200，历史文档预览页面加载成功。学生名册 Excel 上传改走同源代理，用非 Excel 测试文件验证能到达后端文件类型校验，未执行导入。相关变更见 [迁移网页排障 Audit](../.harness/changes/migration-web-recovery-20261121/summary.md)。
